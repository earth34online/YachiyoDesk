# 后续可以加入的有趣点子

2026-10-21。三类桌面接触功能完成后整理，以下是候选方案，不是本轮已实现功能。优先复用既有交互和骨骼求解，保持不开 AI 也能玩。

| 点子 | 实际玩法 | 适配条件与开发边界 |
|---|---|---|
| 桌面小球 | 丢一个小球给角色，角色看球、伸手接住或轻轻踢回；也可用鼠标与她来回传球 | 复用落体、表面接触和手脚 IK；球使用自制简单几何。先做低速可达接球，不牵动人物衣物网格；可关闭且不阻挡正常桌面输入。 |
| 手绘散步路线 | 在透明预览层画几段路线，设置停留点；角色走到那里看看、招手或休息 | 复用现有巡逻与平台支撑；必须检查实际脚底范围、多屏 DPI 和窗口消失。编辑时暂时接管输入，退出后恢复透明区域穿透。 |
| 桌面寻宝 | 放几枚可选的小星星，让角色在你指定的安全路线中寻找；点亮后解锁一段本地对白或动作 | 使用自制图形和本地规则，不读取用户文件、图标或页面。限制活动区域，随时取消，不能覆盖正在操作的窗口按钮。 |
| 角色的回忆相册 | 用户主动保存一次互动、专注完成或明信片，角色可以回顾选中的记录并做出回应 | 扩展现有明信片、专注及可管理记忆；只保存明确选择的内容，不后台截屏。无 AI 可看相册与本地对白，调用自己的 API 时单独展示发送内容。 |
| 双人小剧场 | 选两个有权使用的角色，排练打招呼、击掌和轮流对白；保存成可重复播放的小片段 | 复用小剧场调度，但第二人物会增加渲染和物理开销。先做独立舞台，不把两个原生 Ammo 角色直接塞进日常窗口；碰撞、取消和内存需要单独验证。 |

建议先做“桌面小球”和“手绘散步路线”：与本轮新增能力直接衔接、玩法明确、无需商业 API 或额外模型授权。双人小剧场放后面，先证明单人质量与性能余量。
