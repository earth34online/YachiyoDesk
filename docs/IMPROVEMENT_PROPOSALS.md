## 1. 可导入的动作库

参考 AIRI 的 VRMA 加载与 AnimationMixer 管理，为用户提供本地 `.vrma` 动作导入、预览、循环播放和随机动作列表。VRMA 通过标准人形骨骼适配不同 VRM；官方格式说明见 [VRM Animation](https://vrm.dev/en/vrma/)，AIRI 的相关实现位于 `packages/stage-ui-three/src/composables/vrm/animation.ts`。

收益：可以使用作者制作的完整动作，减少长期依赖程序化欧拉角组合的情况。现有程序化待机、拖动和点击动作仍可作为默认动作。

接入条件：在当前 normalized humanoid 层播放，使用角色自己的骨长；根位移按局部坐标锚定，明确动作与桌面窗口移动谁负责位移；表情、眨眼、视线和身体动作分别管理；播放后仍走同一套衣物物理。停止、打断、循环和物理开关都必须验证。导入动作的授权由其作者决定，不能把找到的动作文件直接作为可再发布资产。

已核对的适配依据：项目现有 `@pixiv/three-vrm` 为 3.5.5，官方 `@pixiv/three-vrm-animation` 存在相同版本，声明的 Three.js peer 范围为 `>=0.137`，包含本项目 0.185.1。AIRI 的 `loadVRMAnimation` / `createVRMAnimationClip` 及局部根轨迹锚定可作为接入参考。当前只核对来源与接口，没有安装该依赖或接入播放功能。

规模：中等，涉及动作文件校验、库管理、播放状态和 UI。建议先以可导入、可预览、可退出恢复默认姿态的完整闭环验收，再增加随机动作编排。

## 2. 导入前的可视化质检

在角色正式加入可用库前，展示纹理、骨骼、比例与动作预览；对文件结构问题提供可定位的说明。可参考 [Khronos glTF-Validator](https://github.com/KhronosGroup/glTF-Validator) 的本地校验与 JSON 报告，再结合项目现有的 VRM/PMX 检查。

收益：减少“导入成功，切换后才发现模型不可用”的情况；用户可以在激活角色前发现丢贴图、动作方向和明显衣物问题。

接入条件：验证在本机完成，模型不上传；临时资源可取消并完整释放；校验报告与实际渲染检查分别显示，结构有效不等于画面已经合格。验证失败不替换活动角色，也不污染角色库。

规模：中等。新增校验器不是替换现有格式检查；应先对已知合法模型测量误报与加载时间。

验收闭环：选择文件 → 本地结构检查 → 使用真实角色 profile 预览 → 确认后加入角色库。取消或失败均保持原活动角色、比例和物理状态；未知 VRM 扩展警告要与实际结构错误区分。官方 [Node API](https://github.com/KhronosGroup/glTF-Validator/blob/main/node/README.md) 提供 `validateBytes`，可与现有事务式导入衔接，不需要上传模型。

## 3. 已撤回的研究方向：后台线程物理

如果后续更复杂模型在本机测试中出现主线程争用，可以单独验证 Worker 中运行刚体物理、主线程继续渲染的方案。[Comlink](https://github.com/GoogleChromeLabs/comlink) 可参考其 Worker 通信与可转移对象的管理方式。

收益：目标是改善 UI 响应与主线程余量，不预先承诺一定提高帧率。

接入条件：骨骼输入、碰撞体和输出使用同一时刻的状态；不能把上一动作的衣物结果套到下一动作；隐藏、恢复、重置和角色切换必须有明确的取消与所有权规则。需要测量线程通信成本、输入延迟、视觉跟随和真实帧时间，不能只比较单次物理运算耗时。

规模：较大。目前约 60 FPS 的样本使用像素比 1；不能用它代表默认最高画质表现。尚未证明该方案在本项目中能保持动作同步、降低总耗时并改善实机体验，因此不列入待实施项目。

## 4. 可操作的模型验收界面

将目前内部使用的多方向、连续动作、开关、重置检查整理为用户可操作的模型验收工具：可选择模型、动作、观察角度，并导出小体积报告和截图。

收益：今后换服装、换骨架或升级依赖时，可以用同一组场景复核，便于你直接比较改动前后。

接入条件：保留真实动作幅度、真实物理路径与角色配置；自动化数值和人工视觉结论分别记录；不得用“碰撞数为零”替代多方向画面验收。报告必须标明具体程序版本、模型指纹和启用的物理后端。

规模：中等。当前内部诊断脚本只用于此次修复验证；是否把它做成正式产品入口，等待你的决定。

## 5. 本地配置快照与回滚

这是针对现有桌宠提出的新增小功能：导出带版本号的设置与角色比例快照，在恢复前预览差异，并保留恢复前快照。复用现有 `SettingsStore` 的字段校验、schema 迁移与角色有效性检查，不替换持久化库，不打包用户模型。

收益：更新程序、切换模型或误调参数后，可以恢复已确认的配置。文件仅含设置；不存在的角色要明确提示并沿用已有回退规则，不依据文件中的绝对路径读取或覆盖外部资产。

验收闭环：导出 → 更改缩放/设置 → 导入预览 → 确认恢复 → 重启仍一致；同时覆盖损坏 JSON、旧 schema、未知字段、缺少角色与取消恢复。规模较小，可在当前设置系统内实现；尚未编写功能代码，等待审查。
