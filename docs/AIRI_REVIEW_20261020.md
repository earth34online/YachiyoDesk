## 通用 PMX 物理流程

1. 导入时保留原始 `physics.pmx`，保存源文件 SHA-256；转换前后检查来源一致性。旧角色只有在已保存的源指纹与转换报告都能证明来源时才自动补全物理资产。
2. 读取 PMX 后，在分配 Ammo 资源之前检查骨骼、刚体、关节索引和数值；物理实例不构建第二套可见模型、纹理或顶点缓冲。
3. 使用绑定矩阵、人体基准轴和尺度建立 PMX 与 VRM 的映射。重复骨名按绑定位置区分，并兼容加载器对空格和重复后缀的处理。实际有权重的骨骼必须能够对应。
4. 每帧先恢复输入骨架，再运行共用人体动作；将姿态映射到原始 PMX，运行其刚体及关节，映射回 VRM。对应 D 变形骨与原始碰撞链一起更新。
5. 被原始 PMX 物理接管的骨骼不再重复运行 VRM SpringBone。转换器新增而源 PMX 没有的辅助关节仍由其 VRM spring 管理器更新。
6. 视角旋转、桌面位置和显示比例不作为物理输入；开关和重置在下一次完整人体姿态准备后同步处理。模型退出时销毁物理世界。

此路径不改变源模型、删除身体网格或缩小动作幅度。启用原始 PMX 后使用完整通用步态；八千代及普通 VRM 沿用各自路径。没有可靠原始 PMX 的旧导入仍可加载，并说明如何重新导入补全原始物理。

## 显示优先的内存管理

- 模型由 Chromium 流式读取，避免主进程先读取完整 Buffer、再构造完整 Response 的重复占用；本机模型响应不保留整文件缓存。
- 同一 runtime 的并发加载共用任务，异步结果不能重新激活已经退出的角色。
- 退出时释放模型几何、材质、纹理、骨骼纹理、阴影目标和物理世界；共享 ImageBitmap 去重关闭。运行中的图像保持可用，以支持 WebGL 上下文恢复。
- 隐藏和最小化停止渲染与物理时钟；对白位置跟随现有渲染回调，避免独立常驻 RAF。
- 不通过缩贴图、隐藏身体、取消物理或降低动作幅度控制内存。内存测量需区分启动峰值、稳定运行和切换后的资源，不用 Windows 工作集下降单独证明无泄漏。

本地文件流式响应遵循 [Electron protocol 官方接口](https://www.electronjs.org/docs/latest/api/protocol) 的 `net.fetch(fileURL)` 用法，仍经过原有目录与文件校验。

## 四套服装的验收方式

测试资产来自本机 `TDA Marin Kitagawa.zip`，仅用于本机验证，不分发模型。四套服装使用同一 `generic-vrm` / `pmx-converted` 配置和同一个后端；每套的骨骼数量、刚体数量、关节数量由源文件决定。

校服、礼服、兔女郎、魅魔均检查初始化、18 个动作及返回、连续行走、物理开关、重置，以及前后左右和四个斜向视角。桌面窗口另检查引导、UI、拖动、隐藏恢复、行走中切换角色和比例恢复。八千代单独回归。

兔女郎原包缺少 `TEX/9.png`（指甲底图）与 `t004.sph`（耳朵叠加球面图）。正式导入保留缺失报错；独立几何/动作测试副本只省略这两张缺失贴图，不改 PMX 原文件，也不把该副本记为完整材质验收。魅魔的蕾丝贴图使用现有唯一乱码文件名恢复规则匹配，保留诊断记录。

视觉验收以各方向看不到明显穿模、拉裂或消失为准，允许极微小相交。三角形相交数只作为诊断。原始 PMX 后端启用本身不代表服饰已验收；正式动作诊断将人体动作与衣物表面结论分别记录。

本机证据集中在 `artifacts/airi-review-20261020`。`extended-*-diagnostics.json` 对应多动作检查，`extended-*-*.png` 对应观察方向，`*-smoke`、`*-soak` 对应真实应用检查。1.x 收尾另见 `artifacts/1x-final-20261020`，包括休息/唤醒、重置与新动作衔接以及四套关键动作的八方向画面。版本记录区分源码推送、本机构建与 GitHub Release。
