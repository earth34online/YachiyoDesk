# 需求与验收清单

这份清单把 YachiyoDesk 从最初的 QPet 替代方案到当前可发布版本的有效要求集中在一处。它既是产品范围，也是发布前回归基线。标记为“已实现”的项目仍需通过自动化或人工观察保持不退化；“兼容边界”不是删减功能，而是模型源数据无法由通用转换器可靠补造的部分。

## 1. 产品范围与交付

- [x] 作为无需 QPet 自定义内容 DLC 的独立 Windows 桌面伴侣运行。
- [x] 本地完整版保留已调好的八千代角色、动作、材质和物理，不因公开版或通用导入功能而回退。
- [x] 公开仓库提供源码、便携版、安装版和 SHA-256 校验文件。
- [x] 本地项目与公开项目隔离；公开仓库不得包含禁止再配布的模型、纹理、PMX、VRM 或模型压缩包。
- [x] 应用图标随源码和安装包发布；任务栏、托盘、桌面快捷方式与安装程序使用同一图标。
- [x] 本地八千代版维持开机自启；设置中可由用户关闭。安装版创建桌面和开始菜单快捷方式。
- [x] 已终止的喜多川海梦应用代码不混入八千代角色扩展体系。

## 2. 启动、窗口和屏幕边界

- [x] 启动完成后默认进入走路状态，而不是永久站立。
- [x] 首次位置在当前显示器右下角，窗口使用物理显示器 `bounds`，人物脚底贴到屏幕底边，不受任务栏工作区影响。
- [x] 初始角色比例为标准全身适配的 35%；缩放改变镜头而不是不断改变原生窗口尺寸。
- [x] 自主移动和拖动都限制在当前显示器完整边界内，人物窗口不能被拖出屏幕。
- [x] 透明背景、始终置顶、透明区域鼠标穿透、位置锁定和鼠标视线跟随均可配置。
- [x] 原生窗口移动保持固定渲染表面，避免走路越走越大、DPI 尺寸漂移和透明窗口反复重建造成的闪烁。
- [x] 应用在任务栏和系统托盘显示图标，关闭窗口不留下无入口的后台进程。

## 3. 自主行为与交互优先级

- [x] 默认沿屏幕底端走动，可选择往返巡逻或随机方向。
- [x] 走路速度可调，默认值兼顾可见脚步与不过快横穿屏幕。
- [x] 多段走路之间随机插入环顾、伸展、鞠躬、轻舞、思考、点头、摇摆、下蹲、踮脚、欢呼等动作，完成后继续走路。
- [x] 点击人物立即停止原生窗口移动，并在同一次交互中回到面向用户的待机姿态。
- [x] 拖动人物使用提起式姿态；松手后重新开始无操作计时。
- [x] 用户主动关闭设置 UI 后，连续 15 秒无交互才恢复默认移动。
- [x] UI 保持打开但连续 15 秒没有点击、按键或表单输入时，主进程自动收起 UI 并立即恢复默认移动。
- [x] 面板关闭 IPC 幂等；重复或迟到的关闭事件不能再次打断刚恢复的行走。
- [x] UI 面板打开期间的真实输入会刷新 15 秒期限，避免用户仍在设置时角色突然走开。
- [x] 自主动作使用独立命令，不会被误判为用户操作并反复重置冷却。

## 4. 动作质量

- [x] 通用动作不只依赖表情或单臂直举，而是同时驱动骨盆、脊柱、胸、肩、上臂、肘、腕、腿和重心。
- [x] 走路时左右腿前后交替、膝盖弯曲、脚踝和可选脚趾滚转；脚步不能只表现为衣摆移动。
- [x] 左右脚不交叉，PMX 转换角色依据实际顶点权重选择腿部变形链，避免人物左脚偏向人物右脚。
- [x] 默认走路朝向约 19°，保留脚步立体感但不过度侧身。
- [x] 手肘保持自然弯曲，小臂不反折，左右手分别计算局部轴。
- [x] 挥手、开心、惊讶、伸展和欢呼使用约 84.8° 的正面腕部滚转；左右掌心朝向观察者、拇指位于靠脸内侧，不会再把左腕错误取反。角色专属轴符号与通用角度分离。
- [x] 下蹲保留为站立屈膝动作。
- [x] 跪坐/跪姿已从内置动作、UI、自主动作和通用 PMX 路径移除，避免在不同骨架和裙装上制造不可接受的姿态与穿模。

## 5. 渲染、衣物和性能

- [x] 八千代既有模型材质、面部、头发、服装和已调 Spring Bone 参数保持不变。
- [x] 渲染器固定透明合成策略并避免逐帧重算会改变画面尺度的动态全身包围盒。
- [x] 拖动和待机状态不应出现整窗闪动；自动化包含多帧像素差异和窗口尺寸稳定性检查。
- [x] PMX 转换区分 OPAQUE、MASK 和 BLEND，避免透明像素黑底、衣服前片消失和错误透明排序。
- [x] MMD 刚体几何不作为可见角色网格导出，但尽可能转换为 VRM Collider/Spring Bone。
- [x] 自适应性能可降低像素比或目标帧率；不得修改模型拓扑、贴图内容或八千代动作参数来换取低质量性能。
- [x] 性能诊断记录平均 FPS、P95 帧耗时、最大帧耗时、像素比、draw calls、三角形、纹理和几何数量。

## 6. UI、状态与对白

- [x] 鼠标靠近人物时显示左侧快捷互动栏，包含饱腹、精力、心情、亲密状态和喂食、饮水、玩耍、休息、夸奖等操作。
- [x] 右键人物打开动作和设置入口。
- [x] 从 UI 选择动作后立即关闭面板；点击人物/UI 以外区域、切换到其他窗口、关闭按钮或 `Esc` 也能关闭。
- [x] 快速打开后立刻关闭会取消尚未执行的显示帧；重复关闭幂等，不会被迟到的动画帧重新显示。
- [x] UI 只保留完成操作所需的文字，详细原理放在项目文档中。
- [x] 参数页覆盖画质、物理、待机、自主活动、巡逻方式、速度、动作频率、缩放、置顶、穿透、锁定和开机启动。
- [x] 对白数据属于角色清单，可为每个角色提供独立性格文本；八千代包含类似“今天桌上有什么新鲜事呢”的桌面闲聊。
- [x] 提供本地专注计时、陪伴状态持久化和完成反馈；数据不会上传。

## 7. 角色库与通用导入

- [x] 可随时导入、切换和删除用户角色；角色分别存放在应用数据目录。
- [x] 直接导入 VRM 0.x/1.0 时校验 GLB/VRM 结构并读取可用元数据。
- [x] 提供独立 PMX 导入入口，调用本机 Blender 将 PMX 转为 VRM 后复用同一运行时，不另建一套低质量播放器。
- [x] PMX 导入是事务式的：校验输入、隔离转换、再次校验输出，失败时只删除本次临时角色目录，不改原 PMX。
- [x] 通用骨骼映射依据名称、层级和实际顶点权重，支持常见 MMD `D`/`EX`/扭转变形骨链，不按“八千代”名字硬编码。
- [x] `generic-vrm`、`pmx-converted` 和角色专属 Motion Profile 分层；只有对各种角色都稳定的优化进入通用层。
- [x] 原八千代路径和专属配置不被后续 PMX 导入逻辑重写。

### 兼容边界

- 标准 VRM 且 humanoid、表情、Spring Bone 完整时效果最好。
- PMX 必须能被 MMD Tools 正常读取，并至少映射出髋、脊柱、头、双臂、双手、双腿和双脚。完全非人形、损坏、加密或缺少关键骨骼的文件会明确失败。
- 转换器能保留的信息上限由源模型决定。缺失纹理、错误蒙皮、原始穿模、特殊自定义 shader、复杂 Morph/刚体/裙摆控制器无法凭空恢复，也不能保证与 MMD 原渲染完全一致。
- 通用导入优先保证可运行和不污染角色库，不会把八千代专属腕轴、裙摆或骨骼补偿套到未知角色。

## 8. 质量门槛和发布检查

- [x] TypeScript 类型检查、单元测试和生产渲染构建必须通过。
- [x] 交互回归必须走真实“主进程命令 → 渲染 UI → preload IPC → 主进程”链路，验证 14 秒内静止、15 秒后 UI 收起和恢复移动。
- [x] Smoke 测试检查模型加载、脚底贴边、图标/窗口基本状态，并重复验证快速外部点击与窗口失焦关闭。
- [x] 掌心单元测试要求左右归一化腕轴同号，并覆盖 PMX 转换配置的双腕整体翻转。
- [x] Motion 测试覆盖走路和全部公开动作的姿态快照与截图。
- [x] Flicker/Soak 测试检查多帧闪动、窗口尺寸稳定、帧时间和 GPU 资源计数。
- [x] 发布包生成后计算 SHA-256；公开包再次扫描，确保不存在 `.vrm`、`.pmx`、模型纹理或模型压缩包。
- [x] Git 提交作者邮箱使用 `3305635414@qq.com`，推送到 `earth34online/YachiyoDesk`，Release 同时上传便携版、安装版和校验文件。

## 9. 模型版权和优先级

- [x] README 明确说明八千代模型来源、作者署名和“再配布：NG”限制。
- [x] 改格式不会绕过原模型条款：PMX 转成 VRM 后仍是受限模型的再发布，因此公开包不包含八千代模型。
- [x] 用户合法取得并在本机导入的模型只留在本机；程序不自动上传模型或纹理。
- [x] 推荐优先级为：有权使用且直接匹配的标准 VRM → 其他标准 VRM → 本机 PMX 转换。
